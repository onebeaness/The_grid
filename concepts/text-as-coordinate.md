# 텍스트로 좌표 만들기

4번 갈래 전체의 요지. **아이템을 좌표에 올리는 한계비용이 거의 0이 된다.** 상호작용 행렬 없이 텍스트만 있으면 된다.

## 파이프라인

세 논문이 하나로 정렬된다.

1. **[[li2023text]] — 텍스트로 충분하다는 증명.** 아이템 ID를 완전히 없애고 key-value 속성 텍스트만으로 시퀀셜 추천. 6개 타깃 도메인에서 NDCG@10 평균 **15.83%**, MRR **15.99%** 개선. zero-shot과 저자원에서 특히 강하다.
2. **[[hu2024said]] — 그걸 싸게 하는 법.** 아이템 ID를 임베딩으로 바꾸는 projector를 두고, 그 임베딩에서 LLM이 **아이템 서술 텍스트를 정확히 생성하도록** 강제한다. 의미를 보존하면서 짧다. 추론 비용이 오프라인으로 이동한다.
3. **[[rajput2023tiger]] — 사람이 읽을 수 있는 코드로 만드는 법.** Sentence-T5 768차원 → RQ-VAE(512/256/128 → 잠재 32) → **3단계 residual quantization, 각 코드북 256** → 충돌 처리용 네 번째 토큰 → **Semantic ID 길이 4**.

그리드 구현 순서로 옮기면:
- 오프라인: 아이템 텍스트 → 의미 정렬 임베딩 저장 (SAID)
- 오프라인: 임베딩 → 계층 코드로 양자화 (TIGER)
- 온라인: 사용자 좌표와 겹침 계산은 저장된 임베딩·코드 위에서만

## 사용자 쪽에도 적용된다

[[sanner2023]]이 아이템이 아니라 **사람** 쪽에서 같은 것을 보인다. 자유 서술 문단만 가진 LLM이 미시청 항목 NDCG@10 0.559를 낸다. 완전 지도학습된 아이템 기반 CF가 0.559~0.577이다.

[[schwartz2013]]과 합치면 온보딩 자유 텍스트 한 칸이 두 가지 일을 한다.
- sanner: 무엇을 추천할지에 대한 정보
- schwartz: 이 사람이 어떤 사람인지에 대한 정보 (Facebook 메시지 7억 단어, 75,000명, 성별 예측 표본 외 정확도 91.9%)

## 왜 텍스트가 그리드에 특히 맞는가

추천 성능 때문이 아니다. [[sanner2023]]의 결론이 말하는 것은 **설명 가능성과 정정 가능성(explainable and scrutable)** 이다.

그리드는 사용자에게 좌표를 보여주고 "이게 맞나요"를 묻는 제품이다. 사용자가 좌표를 고칠 수 있어야 하는데 **벡터는 고칠 수 없고 문장은 고칠 수 있다.**

[[rajput2023tiger]]의 계층 코드가 여기에 하나를 더 얹는다. 연속 벡터는 보여줄 수 없지만 계층 코드는 보여줄 수 있다. 겹침을 **거리**가 아니라 **공유 접두사 길이**로 말할 수 있고, 그게 [[perceived-vs-actual-similarity]]가 요구하는 "일반적 유사성 진술"의 형식과 맞는다.

## 부작용 — 축의 성격이 정해진다

텍스트 기반 좌표는 **설명문에서 나온다.** 그래서 감각 반응 축이 아니라 라벨·서술 축에 가깝다.

[[rentfrow2011music]]의 MUSIC 5요인은 음악 **발췌**에 대한 정서 반응에서 나왔다. 텍스트 설명에서 그 축이 재현될 것으로 기대할 근거가 없다. 오디오 특성 기반 좌표를 따로 두지 않는 한, 우리 음악 축은 [[rentfrow2003stomp]] 계열에 가까울 것이다.

**축에 이름을 붙일 때 이 구분을 지켜야 한다.** → [[latent-space]] [[declared-vs-revealed]]

## 실무 힌트

- [[li2023text]]: 속성을 단순 연결하지 말고 **key-value 구조를 유지**한다. `감독: …`, `분위기: …` 형태.
- [[rajput2023tiger]]: LSH보다 RQ-VAE가 낫다.
- 코드북 256×3단계면 이론상 16.7M 구역. 수백만 아이템 카탈로그가 덮인다.
- 잠재 32차원은 그리드 축(5개 안팎)보다 훨씬 크므로, 그리드 축은 이 공간의 **투영**으로 얻는다.

## 열린 문제

- **하나의 코드북으로 영화·음악·책을 함께 양자화하면 어떻게 되는가.** [[rajput2023tiger]]는 Amazon 카테고리를 따로 학습했다. 그리드에는 이게 핵심 질문인데 아무도 답하지 않았다. → [[domain-transfer]]
- 코드북을 재학습할 때 **Semantic ID가 바뀐다.** 좌표를 저장하고 사용자에게 보여준 뒤 재사용하는 제품에는 실무 리스크다. 어느 논문도 다루지 않는다.
- [[hu2024said]]는 **본문 미확보**다. 실제 성능과 비용 절감폭을 모른 채 파이프라인에 넣고 있다. 본문 확인이 선행돼야 한다.
