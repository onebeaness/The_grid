## 4. 계열 편중 판단

### 초록 필터의 역차별

- 초록 필터 적용 시 교차도메인 추천이 221건에서 62건으로 감소. 72퍼센트 소거
- 표현 학습은 338건에서 107건으로 감소. 68퍼센트 소거
- 소비자행동은 317건에서 166건으로 감소. 48퍼센트 소거
- 원인은 arXiv와 DBLP 레코드에 초록이 없음
- **초록을 필수 조건으로 걸면 공학 계열이 구조적으로 불리**

### 판단 근거 정리

정원제를 택할 근거:

- 계열별 인용수 임계가 2배 이상 차이남
- 문화소비 사회학과 표현 학습이 임계 하위. 통합 순위에서 과소 대표
- 패턴 설명 계열과 구현 수단 계열의 역할이 다름. 같은 척도로 비교할 근거 없음

통합 순위를 택할 근거:

- 계열 건수가 이미 균형. 1.67배 이내
- 우려된 공학 압도가 관측되지 않음
- 정원제는 계열 경계를 고정. 계열 자체가 사후 조정 대상인 단계에서는 부담

### 제3안

- 계열별 하한 정원과 통합 순위 상한을 함께 두는 방식
- 각 계열 최소 N건 보장 후 잔여분은 통합 순위로 배분
- 계열 소거를 막으면서 통합 품질 순위를 유지

## 6. 권고 설계안

결정은 저장소 소유자. 아래는 제안.

### 단계 구성

1. **선행 조건 해소**
   - 1회전 수집 완료. 현재 50/460 작업 잔여
   - `postprocess.py` 실행. 비논문과 근접중복 표시
   - `fetch.py` 실행. 계층 3 규모까지 전문 확보 시도

2. **1차 절단. 계열 정원 + 하한 보장**
   - 각 계열 상위 20퍼센트를 후보 풀로 확보. 약 7,576건
   - 초록을 필수 조건으로 걸지 않음. 공학 계열 역차별 회피
   - 초록 부재 레코드는 fetch 단계에서 초록 확보를 시도

3. **2차 절단. 눈덩이와 내부 피인용 반영**
   - snowball 1회전 실행 후 `unmatched_refs` 반복 횟수 부여
   - 참고문헌 파싱 후 코퍼스 내부 in-degree 부여
   - 두 신호를 인용수와 함께 합산 점수로 사용

4. **3차 절단. 계층 배정**
   - 합산 점수 상위 N건을 계층 1로 배정
   - 나머지를 계층 2와 3으로 배정

### 합산 점수 구성안

각 계열 내에서 백분위로 정규화한 뒤 가중 합산. 가중치는 미정.

| 항목 | 성격 | 가용 시점 |
|---|---|---|
| 계열 내 인용수 백분위 | 외부 신호 | 현재 가용 |
| 질의어 다중성 | 계열 내 중심성 | 현재 가용 |
| 소스 다중성 | 색인 등재 폭 | 현재 가용 |
| 계열 다중 소속 | 갈래 횡단성 | 현재 가용 |
| 눈덩이 반복 등장 | 분야 내 필수 문헌 | snowball 이후 |
| 코퍼스 내부 피인용 | 코퍼스 내 위상 | 참고문헌 파싱 이후 |
| 연도 보정 | 최신 논문 불리 완화 | 현재 가용 |

- 연도 보정 필요. 2024년 이후가 29퍼센트인데 인용 누적 시간이 없음
- 보정 방식 후보 둘. 연간 인용수로 환산, 또는 발행 연도별 백분위 산출
- 어느 쪽도 미검증

### 외부에서 가져온 값과 산출한 값의 구분

CLAUDE.md 62행 준수. 필드로 구분.

- 외부: `citations`, `year`, `venue`, `doi`
- 산출: `score_*`, `percentile_*`, `tier`, `selected`
