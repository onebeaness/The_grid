# 아이템 코퍼스

나무위키 덤프 기반 아이템 코퍼스. 논문 코퍼스(`corpus/`)와 분리. CLAUDE.md 49행.

## 한계

**이 절을 먼저 읽을 것. 4단계 결과로 빈 영역을 논하기 전에 반드시 확인.**

### 스냅샷이 2021-03-01

- 데이터셋 `heegyu/namuwiki`의 실제 시점이 2021년 3월 1일
- 현재 기준 5년 반 경과
- 나무위키 공식 전체 덤프 배포가 이 무렵 중단. 이후 전체 덤프 없음
- 판정 근거는 `snapshot_determination.json`

### 2021년 3월 이후 장르 부재

- 이 코퍼스에 2021년 3월 이후 형성된 장르가 없음
- 미포함 예시: 로그라이트 덱빌딩, 익스트랙션 슈터, 코옵 파티 호러
- 게임 도메인에서 최근 5년간 형성된 장르가 통째로 누락
- 다른 도메인도 같은 성격의 누락 존재 가능. 미확인

### 빈 영역 판정 불가

- 4단계 산출물에서 관측되는 빈칸의 성격이 두 가지로 갈림
- 실제 공백: 아이템이 존재하지 않는 좌표
- 스냅샷 공백: 2021년 3월 이후 생겨 이 덤프에 없는 좌표
- **둘을 이 코퍼스만으로 구분할 수 없음**
- 빈 영역 후보를 실제 공백으로 단정하지 말 것

### 관심 대리 지표의 시간 편향

`genre_matrix.md` 의 평균 본문 길이와 평균 기여자 수에 해당.

- 나무위키에는 판매량도 리뷰 수도 평점도 없음
- 확보 가능한 관심 지표는 본문 길이와 기여자 수 둘뿐
- **둘 다 인기도가 아니라 관심의 대리 지표.** 인기도로 읽지 말 것
- **오래된 게임일수록 문서가 누적됨.** 2000년 게임과 2020년 게임은
  같은 관심을 받아도 누적 기간이 20년 차이. 보정하지 않음
- 기여자 수는 문서 편집 이력의 고유 사용자 수. IP 편집자가 포함되고
  같은 사람이 IP 를 바꾸면 중복 계수됨. `namubot` 과 `관리자` 는 제외함
- 본문 길이는 논쟁이 많은 문서에서 함께 커짐. 호평과 악평을 구분하지 않음
- 문서가 없는 작품은 아예 관측되지 않음. 나무위키 편집자 관심의 하한선이 있음

### 분류 부여 여부와 작품 존재 여부는 별개

- 동시 출현 행렬의 빈 셀은 그 조합의 작품이 없다는 뜻이 아님
- 나무위키 편집자가 그 문서에 두 분류를 함께 달지 않았을 뿐일 수 있음
- 게임 문서 10,446건 중 장르 분류를 2개 이상 가진 것은 1,358건. 13.0퍼센트
- 나머지 87퍼센트는 조합 관측 자체가 불가능

### 그럼에도 유효한 범위

- 파이프라인 검증 가능
- 절 분리 검증 가능
- 분류 매칭 검증 가능
- 축 도출 검증 가능
- 최신 장르 문서 덧대기로 완성. 문서 id를 제목 sha1로 잡은 이유

## 기록해 둘 것

### 붙은 단어의 근본 원인은 노드 트리에 있음

- theseed-bot의 `paragraphs.content`가 줄 단위 `MarkedText` 리스트
- 이 리스트를 개행으로 접합하면 줄 경계가 복원됨
- 후처리 정규식으로는 85퍼센트 감소에 그침
- 구조에서 해결 시 100건 기준 1,848건에서 76건으로 감소
- 파서 교체 시 같은 지점을 먼저 확인할 것

### pgrep -f 는 대기 루프 셸을 오탐함

- `pgrep -f "collect.py"` 가 그 문자열을 포함한 대기 셸 자신을 매칭
- 죽은 프로세스를 살아 있다고 오판. 82분 소실
- `jobs.sh` 사용. `pgrep -x python3` 로 실행 파일명을 정확히 매칭한 뒤 `/proc/<pid>/cmdline` 확인

### nohup 백그라운드가 턴 경계에서 정리됨

- `nohup ... &` 로 띄운 파싱과 수집이 트레이스백 없이 종료
- 메모리 15GB 여유, 디스크 24GB 여유로 자원 문제 아님
- 장시간 작업은 하네스 추적 백그라운드 사용
- 샤드 분할로 중단 시 완료분 보존. `run_parse_shards.sh`
