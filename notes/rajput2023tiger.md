# rajput2023tiger

Rajput et al. (2023). Recommender Systems with Generative Retrieval (TIGER). *NeurIPS 2023*. arXiv 2305.05065
보유: 전문 PDF (`papers/rajput2023tiger.pdf`)

## 무엇을 물었는가

추천에서 아이템을 **무작위 ID**로 표현하는 관행을 버리고, 아이템 콘텐츠에서 유도한 **의미 기반 이산 코드**로 표현하면 어떻게 되는가. 그리고 그 코드를 직접 **생성**하는 방식으로 검색을 대체할 수 있는가.

## 어떻게 측정했는가

**Semantic ID 생성**
1. 아이템 텍스트(제목, 설명 등)를 사전학습 텍스트 인코더에 넣는다. **Sentence-T5**를 써서 **768차원** 의미 임베딩을 얻는다.
2. RQ-VAE로 양자화한다. 인코더는 중간층 512 / 256 / 128 (ReLU), 최종 잠재 표현 **32차원**.
3. **3단계 residual quantization.** 각 단계의 코드북 크기는 **256**.
4. 충돌 처리를 위해 네 번째 토큰을 붙여 **Semantic ID 길이 4**. 총 256×4 토큰으로 전체 코퍼스를 표현한다.

**모델**: 사용자 세션의 Semantic ID 시퀀스를 입력받아 다음 아이템의 Semantic ID를 예측하는 Transformer seq2seq.

**데이터**: Amazon Product Reviews (1996-05 ~ 2014-07) 중 Beauty, Sports and Outdoors, Toys and Games. Beauty와 Sports는 200k 스텝, Toys는 데이터가 작아 100k 스텝. 배치 256, 초기 학습률 0.01.

**콜드스타트 실험**: 테스트 아이템의 **5%** 를 학습 분할에서 제거해 unseen item으로 만든다(누출 방지). Semantic ID 길이 4를 유지하되 앞 3개 코드워드로 unseen 아이템을 후보에 넣는다. 비교 대상은 동일 의미 공간에서 최근접 이웃을 찾는 **Semantic_KNN**.

## 무엇이 나왔는가

- 무작위 ID 대신 Semantic ID를 쓴 추천 시스템이 훨씬 나은 결과를 냈다.
- LSH 기반 Semantic ID보다 RQ-VAE 기반이 나았다(Table 2).
- **콜드스타트**: ε=0.1에서 모든 Recall@K 지표에 대해 Semantic_KNN을 일관되게 상회했고, ε ≥ 0.1 전 구간에서 베이스라인보다 나았다(Fig. 5).
- 추천의 다양성 제어가 가능했다(예측 카테고리 분포의 엔트로피, Table 3).

## 우리 좌표계로 옮기면

**그리드의 아이템 배치 메커니즘이 여기 있다.**

TIGER가 주는 것은 두 가지다.

**첫째, 아이템 콜드스타트의 소멸.** 신규 아이템도 텍스트만 있으면 즉시 좌표를 얻는다. 상호작용 이력이 필요 없다. 그리드에서 새 영화, 새 앨범, 새 책이 나올 때마다 사용자 데이터를 기다릴 필요가 없다는 뜻이다. 이게 4번 갈래 전체가 그리드에 주는 가장 큰 선물이다. → [[concepts/cold-start]]

**둘째, 계층적 이산 코드라는 표현 형식.** 3단계 residual quantization은 거친 것에서 세밀한 것으로 내려가는 계층을 만든다. 그리드에서 이건 **취향 구역(neighborhood)의 이름표**가 된다.

- 첫 코드워드 = 큰 영역
- 둘째 = 그 안의 구역
- 셋째 = 세부

연속 벡터는 사용자에게 보여줄 수 없지만 계층 코드는 보여줄 수 있다. "당신은 [3-17-91] 구역에 있고, 이 사람도 [3-17] 까지 같습니다" 같은 표현이 가능해진다. 겹침을 **거리**가 아니라 **공유 접두사 길이**로 말할 수 있다는 것은 [[concepts/perceived-vs-actual-similarity]]에서 요구하는 "읽히는 유사성"에 직접 쓸모가 있다.

숫자도 그대로 참고 가능하다. 256짜리 코드북 3단계면 이론상 16.7M 구역이다. 아이템 카탈로그가 수백만 규모여도 덮인다. 잠재 32차원은 그리드 축 개수(5개 안팎)보다 훨씬 크므로, 그리드 축은 이 잠재 공간의 **투영**으로 얻는 것이 자연스럽다.

## 이 논문이 배제하는 것

- **아이템 ID가 임의여도 무방하다는 관행**을 배제한다. 의미 기반 ID가 일관되게 나았다.
- **신규 아이템에는 상호작용이 쌓일 때까지 기다려야 한다는 가정**을 배제한다.
- **LSH 같은 단순 해싱으로 충분하다는 가정**을 배제한다. RQ-VAE가 나았다.
- 이 논문은 **교차도메인을 다루지 않는다.** 각 Amazon 카테고리를 따로 학습했다. 한 코드북으로 영화·음악·책을 함께 양자화하면 어떻게 되는지는 미검증이고, 그리드에는 그게 핵심 질문이다.
- **사용자 콜드스타트**를 다루지 않는다. 아이템 쪽만이다.
- 코드북 붕괴, 시간에 따른 코드 재학습 시 ID 불안정성 문제는 다루지 않는다. 좌표를 저장하고 재사용하는 제품에는 이게 실무 리스크다.
